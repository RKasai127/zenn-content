## HTTPヘッダーの種類

HTTPヘッダーといわれると、`Content-Type`や`Content-Length`を思い浮かべる人が多いのかなと思います。

どちらもHTTPヘッダーですが、MDNではさらに細かく分類されています。

たとえば `Content-Type` は表現ヘッダー(`Representation header`)、`Content-Length`はペイロードヘッダー(`Payload header`)に分類されています。

分類と役割を表にまとめると以下になります。

| 分類 | 役割 | 例 |
| --- | --- | --- |
| リクエストヘッダー(`Request header`) | 取得するリソースや、クライアントについての追加情報を持つ | `Host`、`Cookie` |
| レスポンスヘッダー(`Response header`) | レスポンスの場所や、サーバーなどの追加情報を持つ | `Location`、`Server` |
| 表現ヘッダー(`Representation header`) | 本文の形式や圧縮方式などの情報を持つ | `Content-Type` |
| ペイロードヘッダー(`Payload header`) | 本文の長さや、転送用のエンコーディングなどの情報を持つ | `Content-Length` |

この記事では、リクエストヘッダーとレスポンスヘッダーに絞って、代表的なものとその役割を表にまとめていきます！！

## リクエストヘッダー

リクエストヘッダーとは、サーバがレスポンスを適切に調整できるように、どんな情報を返せばよいかのコンテキストを定義するヘッダーです。

家系ラーメンに例えると、麺の硬さ、スープの濃さ、鶏油（チーユ）の量はお客さん(クライアント)の好みによって変わります。その好みをラーメン屋(サーバー)に伝えるのがリクエストヘッダーです。

実際のヘッダーでは、誰なのか(`Authorization`)、また何語(`Accept-Language`)か、どのサイト宛(`Host`)などを送ります。

以下のようなヘッダーがあります。

| ヘッダー名 | 役割 | 値の例 |
| --- | --- | --- |
| [`Host`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Host) | 接続先のホストとポートを伝える | `example.com` |
| [`User-Agent`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/User-Agent) | クライアントの種類を伝える | `curl/8.5.0` |
| [`Accept`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Accept) | 受け取れるデータ形式を伝える | `application/json` |
| [`Accept-Language`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Accept-Language) | 希望する言語を伝える | `ja,en;q=0.5` |
| [`Accept-Encoding`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Accept-Encoding) | 対応している圧縮方式を伝える | `gzip, deflate, br, zstd` |
| [`Authorization`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Authorization) | 認証情報を送る | `Bearer <token>` |
| [`Cookie`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Cookie) | 保存しているCookieを送る | `sessionId=abc123` |
| [`Referer`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Referer) | リクエスト元のページのURLを伝える | `https://example.com/page` |
| [`Origin`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Origin) | リクエスト元のオリジンを伝える | `https://example.com` |
| [`If-None-Match`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/If-None-Match) | 持っているデータの版(ETag)を伝える | `"33a64df5"` |
| [`If-Modified-Since`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/If-Modified-Since) | 持っているデータの更新日時を伝える | `Wed, 21 Oct 2015 07:28:00 GMT` |
| [`Range`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Range) | 取得したい範囲を伝える | `bytes=0-99` |

## レスポンスヘッダー

レスポンスヘッダーとは、レスポンスそのものについての追加情報を、サーバーからクライアントに伝えるヘッダーです。

家系ラーメンに例えると、ライス無料、や、水はセルフ、のような、ラーメンそのものではなく、ラーメン屋(サーバー)からの案内にあたります。

実際のヘッダーでは、次回も送ってほしい値(`Set-Cookie`)、移動先のURL(`Location`)、どのサーバーが返したか(`Server`)などを送ります。

以下のようなヘッダーがあります。

| ヘッダー名 | 役割 | 値の例 |
| --- | --- | --- |
| [`Set-Cookie`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Set-Cookie) | Cookieの保存を指示する | `sessionId=abc123; HttpOnly; Secure` |
| [`Location`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Location) | リダイレクト先のURLを伝える | `/new-page` |
| [`ETag`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/ETag) | データの版の識別子を伝える | `"33a64df5"` |
| [`Last-Modified`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Last-Modified) | データの最終更新日時を伝える | `Wed, 21 Oct 2015 07:28:00 GMT` |
| [`Vary`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Vary) | 返答の内容を左右したリクエストの要素を伝える | `Accept-Encoding` |
| [`Server`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Server) | サーバーのソフトウェアを伝える | `nginx` |
| [`WWW-Authenticate`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/WWW-Authenticate) | 必要な認証方法を伝える | `Basic realm="Dev"` |
| [`Retry-After`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Retry-After) | 再試行までに待つ時間を伝える | `120` |
| [`Access-Control-Allow-Origin`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Access-Control-Allow-Origin) | レスポンスの読み取りを許可するオリジンを伝える | `*` |
| [`Strict-Transport-Security`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Strict-Transport-Security) | HTTPSでの接続を指示する | `max-age=63072000` |
| [`Content-Security-Policy`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Content-Security-Policy) | 読み込めるリソースを制限する | `default-src 'self'` |
| [`X-Content-Type-Options`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options) | `Content-Type` の形式を推測で変えないよう指示する | `nosniff` |

## 表現ヘッダー

表現ヘッダーとは、本文をどう解釈すればよいかを説明するヘッダーです。

ラーメン屋に例えると、会計のときにカードでと言って、クレジットカードを渡すような状況が分かりやすいかと思います。(家系ラーメン屋でカード決済はあまりないかもしれませんが)。
カードそのものが本文で、その種類を説明するのが表現ヘッダーです。券売機、あるいはお店がクレジットカードに対応していなければ戻されるように、サーバーが対応していない形式の本文は `415(Unsupported Media Type)` で断られることがあります。

本文を送る側が付けるヘッダーなので、リクエストにもレスポンスにも使われます。

実際のヘッダーでは、本文の形式(`Content-Type`)、圧縮方式(`Content-Encoding`)、言語(`Content-Language`)などを送ります。

以下のようなヘッダーがあります。

| ヘッダー名 | 役割 | 値の例 |
| --- | --- | --- |
| [`Content-Type`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Content-Type) | 本文の形式を伝える | `text/html; charset=utf-8` |
| [`Content-Encoding`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Content-Encoding) | 本文の圧縮方式を伝える | `gzip` |
| [`Content-Language`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Content-Language) | 本文の対象言語を伝える | `ja` |
| [`Content-Location`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Content-Location) | 本文のデータの別の場所を伝える | `/my-receipts/38` |

## ペイロードヘッダー

ペイロードヘッダーとは、本文の運ばれ方を説明するヘッダーです。

家系ラーメンに例えると、ラーメンと目玉丼を頼んだ際に、店員(サーバー)から、「目玉丼は後からお持ちしますね！」という一言にあたります。「こちら目玉丼です」のように何が届いたかを説明するのが表現ヘッダーで、どう届くかを説明するのがペイロードヘッダーという違いがあります。
(目玉丼については、[おまけ2](#おまけ2%3A-本記事で元にしたラーメン屋)で説明しています。)

本文を送る側が付けるヘッダーなので、リクエストにもレスポンスにも使われます。

実際のヘッダーでは、本文の大きさ(`Content-Length`)、全体のどの部分か(`Content-Range`)、転送時の形式(`Transfer-Encoding`)などを送ります。

MDNの用語集では、以下のヘッダーが紹介されています。

| ヘッダー名 | 役割 | 値の例 |
| --- | --- | --- |
| [`Content-Length`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Content-Length) | 本文のバイト数を伝える | `1024` |
| [`Content-Range`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Content-Range) | 全体のどの部分かを伝える | `bytes 0-99/577` |
| [`Transfer-Encoding`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Transfer-Encoding) | 転送時の形式を伝える | `chunked` |
| [`Trailer`](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Headers/Trailer) | 本文の後に追加するヘッダーを伝える | `Server-Timing` |

## おまけ: 追悼のヘッダー

HTTPヘッダーの中には、通信の役には立たないのに、世界中のサーバーから送られているものがあります。それが、作家テリー・プラチェットを追悼する `X-Clacks-Overhead` です。

手元のターミナルで確認できます。

```bash:X-Clacks-Overheadを確認できます。
curl -sI https://www.debian.org | grep -i clacks
```

```text:結果
x-clacks-overhead: GNU Terry Pratchett
```

由来は、プラチェットの小説シリーズ「ディスクワールド」にあります。作中には、電信のように塔から塔へ信号を送る「Clacks」という通信網が登場します。

小説『Going Postal』では、Clacksの発明者の息子ジョンが亡くなります。その名前を残すため、`GNU John Dearheart` という信号が通信網に流され続けました。`GNU` は、次のような指示を組み合わせた符号です。

| 文字 | 意味 |
| --- | --- |
| `G` | メッセージを次の塔へ送る |
| `N` | メッセージを記録に残さない |
| `U` | 終点に着いたらメッセージを折り返す |

この指示により、名前は通信網が続く限り流れ続けます。作中の言葉に、次のようなものがあります。

> A man is not dead while his name is still spoken.
> (その名が語られている限り、人は死なない)

2015年にプラチェットが亡くなると、ディスクワールドのファンが集まるRedditのコミュニティで、この信号をHTTPヘッダーで流す案が生まれました。標準化されたヘッダーではありませんが、今もDebianやPythonのドキュメントのサイトが返しています。
